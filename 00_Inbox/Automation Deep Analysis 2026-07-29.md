# Automation Deep Analysis: Websites, Design, Indeed Outreach

This is the deeper cut on three automation lanes plus the infrastructure layer that makes them compound. Everything below is grounded in what already exists in this vault — the goal is to name exactly what to build, what it feeds on, what it produces, and in what order, ranked against the three written targets: **$40K Mohr Media in 5 months**, **ROAD TO 100 CLIENTS (12/100)**, and **2,000 book subscribers**.

## The one-paragraph verdict

You already own most of the hard parts. `philly-sites` proves you can mass-produce polished prospect homepages (25 shipped in one batch). The IMMOHRTAL `asset-studio` proves you can render ~50 finished design assets from code and design tokens. The `_os/reporting` factory and `/client-report` skill prove branded HTML reports from JSON. The 64GB Orchestrator spec already defines the approval-tier contract. What's missing is **connective tissue**: none of these engines are multi-client, none run on a schedule, and none feed an outreach pipeline. The Indeed lane is the only genuinely new build — and it's the one that directly attacks 12→100 clients, because a business paying to hire a marketer is a pre-qualified buyer for "marketing without hiring in-house," which is literally the Mohr Media positioning in [[05_Offers/Mohr Media Business Plan]].

## Lane 1: Website automations

### What exists today (the evidence)

- **`philly-sites/`** — 25 static prospect homepages (PHL011–PHL035), each a single-file HTML with a `data-profile-id` design theme, built from Netlify drafts, then hand-passed with a repeated `/* design upgrade layer */` CSS block pasted per file. This is a working factory run — done manually.
- **`mohr-media-site/`** — 20 production pages generated by scratchpad scripts (`build2.py`/`build3.py` + `blogs.json`) that live outside the repo; deployed by hand via `vercel deploy --prod` with no git link.
- **`immohrtal-site/`** — the most automated property: `gen-blog-pages.mjs` (permalinks/sitemap/RSS), `indexnow-ping.mjs` (AEO ping), `set-domain.mjs` (origin cutover). All still manually invoked.
- **The book site failure** — the signup form posted to a nonexistent `/api/dossier-leads` for ~2 months and nothing caught it. That's the cost of having zero site monitoring: the entire 2,000-subscriber goal sat dead.
- **Client site work in flight** — Onsite Concrete Divi repair, Shadow HVAC Next.js rebuild, Bar Crawl 20-city WordPress publisher (page ID 15281), KJB Squarespace SEO pages, NKCDC LP blocked.

### W1. Website Factory pipeline (the productized offer — Opp #7)

The philly-sites run, turned into a repeatable machine instead of a one-off sprint.

- **Trigger:** new prospect name + URL dropped into a `Factory Queue.md` (or fed automatically from the Indeed lane below).
- **Pipeline:** scrape brand assets (logo, palette, photos, NAP, menu/offers) → select a design profile from the existing `data-profile-id` theme library → generate the single-file homepage from template → deploy immutable Netlify draft → append to a private review gallery index (exactly like `philly-sites/index.html`).
- **Output:** a pitch-ready demo homepage per prospect in minutes, `noindex`, deep-linking their real properties.
- **Why it matters:** this is simultaneously (a) the sales weapon for outreach ("here's your site, rebuilt — want it?"), (b) the fixed-scope Mohr Media product ("site in days, not weeks"), and (c) the delivery engine for the $4,000 Website Conversion Overhaul in the business plan.
- **Build note:** the 25 existing pages ARE the template corpus. Extract the shared section skeleton (`#top / #offerings / #gallery / #visit`) and the theme profiles into a generator; stop pasting the design-upgrade CSS layer into every file and make it a shared module.

### W2. Deploy + post-deploy pipeline (kill the manual ship steps)

- Git-link the Vercel/Netlify projects so `git push` deploys (mohr-media-site currently deploys only from Dillon's terminal; the generators aren't even committed).
- Commit `build2.py`/`build3.py` (or port them to the repo) so pages regenerate from content JSON instead of hand-editing HTML.
- Chain the immohrtal scripts into a single post-deploy hook: rebuild → sitemap/RSS → IndexNow ping → (on domain change) `set-domain.mjs`. One command, or zero commands on push.
- Analytics IDs injected as env vars at deploy — the immohrtal measurement layer is fully wired and dark only because IDs were never pasted.

### W3. Site health sentinel (the /api/dossier-leads insurance policy)

A scheduled check (daily, Tier 0, cloud-safe) across every property you own or manage: book site, mohr-media, immohrtal, and client sites.

- **Checks:** form endpoints actually accept a POST (submit a canary lead, verify it lands), tracking tags present and firing (GA4 / Meta Pixel / GTM published — the orchestrator spec already lists this as pre-flight), broken links, SSL/domain expiry, Lighthouse score drift.
- **Output:** one line per property in the morning brief; red items surface on the approval board.
- **Why it matters:** a two-month dead form on the book site is the proven failure mode. This automation costs almost nothing and prevents the worst class of silent loss.

### W4. Landing page lane (client delivery)

Generalize the Bar Crawl 20-city WordPress publisher pattern into the `landing-page-generator` skill referenced in Opp #7: brief in (city/service/offer JSON) → LP out on the client's stack (WordPress/Elementor, Squarespace, GHL, Netlify — the Lane D list from the 64GB handoff). Immediate consumers: NKCDC tax-prep LP (the unblock), Replenish, Omega, SmartCare `/align-hcm-smartcare`.

### W5. Report factory, one command per client (Opp #5, restated as a website automation)

`_os/reporting/build-report.js` + the `/client-report` skill already render branded HTML from JSON. The missing 80% is the **data pull**: per-client fetchers (Google Ads, Meta, GA4, GBP) that emit the JSON the template eats. Then: `report <client>` → pull → render → publish to Netlify → share link. This erases the single biggest recurring manual load (Align + ~8 M360 retainers monthly).

## Lane 2: Design automations

### What exists today

- **IMMOHRTAL `asset-studio`** — Python + Playwright + Pillow pipelines (`render.py`, `motion.py`, `clips.py`, `splitcards.py`, `ogcards.py`, `epk.py`) that produced ~50 finished assets (35 statics, 27 motion, EPK PDF) from the site's design tokens. This is a real, working, code-driven design studio — for exactly one brand.
- **Client brand data already structured** — nearly every client folder has `brand-guidelines.md`. The report factory already consumes brand palettes.
- **Recurring design demand:** GBP posts at 4×/week for Shadow HVAC, Omega, Hardwood Artisan + 3×/week for Jeff Hozias (≈15 posts/week), Bok Law weekly social series, Align LinkedIn across 5 profiles (Mon/Wed/Fri cadence with three motion formats), monthly report visuals, ad creatives for Meta tests.

### D1. Multi-client asset studio (the highest-leverage design build)

Take `asset-studio` and make the brand a parameter instead of a constant.

- **Input:** a `brand-tokens.json` per client, generated once from each `brand-guidelines.md` (palette, fonts, logo path, voice rules).
- **Pipelines to generalize first:** quote/stat cards, story covers, OG images, carousel frames — these cover GBP posts, LinkedIn statics, and report headers in one engine.
- **Output convention:** `01_Clients/<Client>/assets/YYYY-MM/` with predictable names so the content calendar and GBP publisher can reference them.
- **Why it matters:** ~15 GBP posts + weekly social series + Align cadence is 25–30 designed artifacts/week, currently hand-made. One parameterized renderer converts that to a review-and-approve flow.

### D2. GBP content factory

Sits on top of D1: weekly batch per GBP client → pull recent work/photos/seasonal angle → generate post copy (respecting per-client rules) + rendered image → queue as drafts. Publishing stays Tier 2 (approval-gated) per the orchestrator contract, same as the existing `bok-law-social-content` Sunday routine — which is the proof this cadence pattern works and just needs 4 more clients on it.

### D3. Social series generator (Bok Law / Align patterns → template)

`bok-law-social-content` (Sun 6 PM) and `linkedin-growth-engine` (Sun 9 PM) already exist as routines. Refactor them into one parameterized `social-series` skill: series definition in (pillars, cadence, formats, voice rules like "no em dashes" for Align) → week of drafted posts + D1-rendered visuals out. Adding a new client's social retainer becomes config, not a new build.

### D4. Creative pre-flight guardrail (Opp #4, scoped to design)

Before any creative reaches a queue: banned-terms lint (Bar Crawl alcohol language), brand palette/logo verification (Replenish branding rule), required elements (KJB CC list on sends), platform spec check (dimensions, text density). This is the machine-enforceable version of the disapproval history — Bar Crawl ad rejections and the Soulard $54 runaway are the documented reasons the empty `11_Agents` shells need filling. Every D1–D3 output passes through it automatically.

### D5. Demo-site design pass as a module

The `/* design upgrade layer */` block pasted into 25 philly-sites files becomes a versioned shared stylesheet + post-processor in the W1 factory. One improvement then upgrades every future demo instead of requiring 25 more pastes.

## Lane 3: Indeed outreach (the client-acquisition engine)

**Interpretation check.** The vault has zero job-search, resume, or application-tracking content — `02_FullTimeJob/` is the Align HCM W2 role. The reading that fits everything in this vault: **use Indeed job postings as buying signals for Mohr Media prospecting.** A business posting a $50–70K marketing hire has (a) budget, (b) an admitted marketing gap, and (c) urgency — and the business plan's core pitch is "senior-level marketing without hiring in-house." The plan already commits to 20–30 cold emails + 10–15 LinkedIn DMs per week (Opp #8 flags that these sequences were never built). This lane builds the machine that fills that quota with the warmest possible cold list. *(If the intent was ever applying to jobs, the same scrape/enrich/draft skeleton works — swap the pitch for a tailored application — but nothing in the vault points there, so it's parked.)*

### I1. Hiring-signal scraper

- **Query set:** Indeed (plus LinkedIn Jobs and Google Jobs as secondary sources) for roles like *marketing manager, digital marketing specialist, social media manager, SEO specialist, marketing coordinator* — filtered to SMB-sized companies in target metros (Philly footprint from the philly-sites run, Fredericksburg/NoVA, Erie) and Mohr Media's verticals (home services, legal, medical/dental, restaurants, e-commerce — the client roster's actual shape).
- **Cadence:** daily or 3×/week, Tier 0, cloud-safe.
- **Mechanics note:** Indeed has no public API and blocks naive scraping — use a compliant path: a scraping API (SerpAPI/Apify-class), Google Jobs results, or CDP-assisted browsing on the 64GB machine consistent with the existing Chrome-lane pattern. The signal (company is hiring for marketing) is what matters, not bulk data extraction.
- **Output:** `08_Prospects/Hiring Signals.md` rows — company, role, salary band, posting date, location, source link.

### I2. Enrichment + qualification scorer

For each signal, an automated dossier: website URL and a quick teardown score (speed, mobile, forms, tracking present — reuse W3's checks), GBP status and review count, whether they're running ads (Meta Ad Library + Google Ads Transparency Center lookups), estimated fit tier. **Then the kicker: pipe A-tier prospects straight into the W1 Website Factory** so the outreach email can include a live rebuilt-homepage link. That fusion — hiring signal + personal demo — is the differentiated play nobody cold-emailing them has.

### I3. Draft-first outreach sequencer

- **The math pitch, templated:** "The role you posted costs ~$65K + benefits + 3 months ramp. The [[05_Offers/Mohr Media Business Plan]] Growth retainer delivers the same functions at $1,500–$3,000/mo, starting next week — here's your website rebuilt as proof: {demo link}."
- **Sequence:** email 1 (demo + math) → day 3 LinkedIn DM → day 7 email 2 (one specific finding from the teardown) → day 14 breakup email with the $497 audit as the downsell.
- **Boundaries:** drafts only, batch-approved before send — identical to the Gmail/Slack draft-first contract already in the orchestrator spec. Sends are Tier 2, always.
- **Volume target:** fills the plan's 20–30 emails + 10–15 DMs/week from the scored list automatically instead of from manual hunting.

### I4. Pipeline tracking + revival sweep

The Client Index's Prospects section is empty. Give every contacted company a prospect note with `status / last_touched / next_action` frontmatter (the exact schema Opp #11 mandates for clients), so `client-pulse` can watch prospects the same way it watches clients. Fold reply-chasing and the stalled-client revival sweep (Opp #6 — NKCDC, Hardwood, Shadow, Omega) into the same follow-up engine: one machine that never lets a thread die silently, inbound or outbound. Weekly, the funnel numbers (signals found → enriched → contacted → replied → audits booked → retainers closed) land in the revenue scorecard (Opp #9).

## Build order (dependency-sequenced, not calendar-boxed)

**Wave 1 — unblock and instrument (small, immediate):**
frontmatter revival → W3 site sentinel (canary the book form first) → git-link deploys + commit the site generators (W2).

**Wave 2 — the acquisition engine (attacks 12→100 directly):**
I1 scraper → I2 enrichment → I3 sequencer drafts (sends gated) → I4 prospect frontmatter + pulse integration. First outreach batch can go out with manual demos before W1 is automated.

**Wave 3 — the factories (delivery capacity):**
W1 website factory (extract the philly-sites templates) → D1 multi-client asset studio → W5 report data pulls → D2 GBP factory on top of D1.

**Wave 4 — compounding layer:**
D3 social-series generalization → D4 creative guardrails wired into everything → W4 LP lane → scorecard + HUD v2 cards (Opp #13) showing factory throughput and funnel counts.

The ordering logic: Wave 1 stops silent losses and makes truth current. Wave 2 starts filling the pipeline while factories are being built — outreach with hand-picked demos beats no outreach. Wave 3 scales delivery so closed prospects don't create a fulfillment crunch. Wave 4 makes every future client cheaper to serve than the last.
