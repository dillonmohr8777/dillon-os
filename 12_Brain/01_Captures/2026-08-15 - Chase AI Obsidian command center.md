# Chase AI Obsidian command center

## Why this matters

The video presents Obsidian as an operating surface over a skill catalog,
scheduled automations, precomputed reports, a navigable Markdown knowledge
layer, and an optional local voice interface. The useful principle is not the
featured provider or visual treatment. It is that the interface should expose
real operating state and make proven workflows easier to invoke.

## Verified source snapshot

- The canonical TikTok post is `7674342462638378253`, published by Chase AI on
  2026-08-15 with the title `obsidian x claude os 2.0`.
- TikTok exposed a 24 minute 17 second English auto-caption track. The capture
  was compiled from that track and the post metadata.
- The source proposes a custom Obsidian command center with at-a-glance metrics,
  calendar context, morning intelligence, report views, and buttons for common
  skills and automations.
- Its voice example uses local speech recognition, a small routing model, three
  execution lanes, and local text to speech. The named components are Faster
  Whisper for transcription and Kokoro for speech output.
- The knowledge pattern separates source material, compiled knowledge, and
  deliverables, then adds nested index files so a human or agent has an explicit
  retrieval map.
- The automation guidance is to codify repeated work as an on-demand skill,
  prove the output through use, and only then schedule it as an automation.

## Fit with Dillon OS

### Already stronger here

- `INDEX.md`, Brain Home, the Knowledge Atlas, Bases, and canonical numbered
  folders already provide the retrieval map. Replacing them with a generic
  `raw/wiki/output` tree would discard stronger routing and client separation.
- The automation registry, workflow gate, approval tiers, immutable captures,
  precomputed daily intelligence, report archive, and guarded learning loop
  already provide the substance behind a command center.
- Codex acting as Marketing Chief already owns routing, canonical compilation,
  approvals, and final verification.

### Adopted now

- The root Dashboard exposes a Codex command surface over the existing trusted
  views instead of creating a second source of truth.
- The automation concept now contains an explicit skill-to-automation promotion
  gate and a fast-answer routing pattern.
- The existing local voice sandbox is now framed as a Codex command layer with
  deterministic, precomputed-answer, and bounded-agent lanes.

### Deliberately not adopted

- No Claude-specific configuration, prompt files, process invocation, or
  provider routing from the video.
- No vault restructure into `raw/wiki/output`.
- No Hot Reload or other GitHub-only Obsidian plugin install without the normal
  source, permission, network, and rollback review.
- No microphone permission, global hotkey, background execution, or custom
  command plugin until the sandbox acceptance contract is approved and passed.
