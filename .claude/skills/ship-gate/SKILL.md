# Ship gate (one methodology)

One-line: Grill the work, then ship. One checklist. Pick was mattpocock/skills (grill / TDD / implement), not a stack of three frameworks.

## Why one

Stacking Superpowers + Addy Osmani + Pocock produces three overlapping sermons and zero ships. Factory volume needs one gate.

## Gate (in order)

1. **What did we claim?** Open the page. Every number, name, and URL must exist in a `source:` or live fetch. Drop the line if unmarked.
2. **Would a stranger believe this is the real business?** NAP, phone, hours, service area, harvested palette. Fail if it looks like a template farm.
3. **Human still owns the send.** QR / mail / Slack / WordPress publish stays draft. `mail_ready` remains `hold` until Mac.
4. **Tests that exist, run.** For vault/OS work: `node --test _os/test/brain-hud.test.js _os/test/public-safety.test.js`. For a static site: open the HTML, click the phone link, check contrast.
5. **Kill criteria.** If the artifact cannot name a 90-day kill switch (pilots) or a rollback (pages), it isn't ready.

## Not this gate

- Inventing AEO retainers
- Presenting Cedar Ridge as a client
- Dumping 25 dead-domain rebuilds as "the batch"
- Sending Slack or Gmail because the draft exists
