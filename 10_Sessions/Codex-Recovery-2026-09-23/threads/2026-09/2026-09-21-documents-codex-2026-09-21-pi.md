> If Docker Desktop "Start Docker Desktop when you sign in" is off, nothing resumes after Windows reboot until Docker Desktop / engine is started manually. `restart: unless-stopped` only acts when the Docker daemon is running.
> 
> Official behavior:
> 
> - Auto-start setting defaults to Disabled; Desktop must be launched after sign-in: https://docs.docker.com/desktop/settings-and-maintenance/settings/
> - `unless-stopped`: restarts container on exit or daemon restart, but not if it was manually stopped: https://docs.docker.com/engine/containers/start-containers-automatically/
> - Caveat: policy applies only after a container stayed up >= 10 seconds; a manually stopped container stays stopped until daemon restart or manual `start`. A past Docker bug also notes `unless-stopped` may not be honored during engine shutdown, so verify state.
> - `compose stop`: stops containers without removing them; resume with `compose start`: https://docs.docker.com/reference/cli/docker/compose/stop/
> - `compose down`: stops plus removes containers and Compose networks; by default it does not remove named volumes, images, external networks/volumes, and anonymous volumes will not remount on next `up`: https://docs.docker.com/reference/cli/docker/compose/down/ and https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-docker-compose/
> 
> Read-only validation, in order: `docker version`, `docker ps -a`, `docker compose ls`, `docker compose -p <project> ps`, `docker compose config`, `docker logs --tail 50 <svc>`.
