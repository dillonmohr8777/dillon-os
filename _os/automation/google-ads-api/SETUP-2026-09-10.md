## What `--diagnose` settles

Five calls on one bearer token:

| # | Target | `login-customer-id` | Answers |
|---|---|---|---|
| 1 | — | omitted | what this token actually sees |
| 2 | `7038673437` | **omitted** | **does the MCC work outside Composio?** |
| 3 | `7038673437` | `7038673437` | explicit self-route |
| 4 | `2853981364` | omitted | is Standard access enough? |
| 5 | `2853981364` | `7038673437` | does the manager route work? |

**Call 2 is the one that matters.** If the MCC answers a header-free local
request while Composio's identical request returns 403, the fault is provably
Composio's routing and it comes out of the architecture. If call 2 also fails,
it was never Composio.

## Known limits to plan around

  probe; the app must be published before any daily automation depends on it.
- **Explorer is 2,880 operations/day.** Batch queries; do not poll.
- **`627-501-4654` carries Replenish AND Fresh Blends.** Never take an
  account-level total there. The campaign-name allowlist is still unwritten.
- **`721-491-4099` is a cancelled KJB duplicate.** Never query it.
- Read-only until the API is verified end to end. No campaign, budget, bid, ad,
  keyword, conversion, manager-link or permission change.

## Fallback transport, deliberately not primary

Google Ads Scripts (`AdsManagerApp` + `executeInParallel` + `AdsApp.search`)
need no developer token at all because they run inside the Ads UI. That remains
the fallback and the likely path for **mutations** later, since
`AdsApp.mutate()` is available there. It is not the primary data transport now
that the API is open.
